# 제작 및 검증 결과

## 신호의 항구

귀환안과 해도안은 원래 타이밍으로 각각 전체 MP4를 재생했다. 귀환안은 종이 해안의 등화에서 시작해 방위계의 회전을 충분히 보여 준다. 뒤의 배가 파도 무늬에 묻혀 항로가 생기는 변화는 약했다. 해도안은 앞서 해안으로 돌아오고 항로 눈금을 남긴다. 눈금과 문구는 새 상황을 설명하지만 배가 출발하는 위치와 방위계의 끝점을 연결해 보여 주지 못했다. [귀환안 재생](harbor-draft-playback.jpg) · [해도안 재생](harbor-map-draft-playback.jpg)

착안은 첫 등화 뒤에 짧은 입사선을 놓고, 방위계 구간을 88–219프레임으로 줄였다. 219프레임에서 방위계가 발행한 끝점 `(158.22, 375.15)`를 220프레임의 항로와 배의 시작에 쓴다. 컷은 유지한다. 컷 뒤 배를 더 크게 그리고 등화가 다시 들어올 때 배 주변에 따뜻한 물결을 놓았다. 전체 착안 러프에서 배가 방파제 위로 올라가는 결함을 발견했다. 끝점을 수면 앞으로 옮긴 뒤 최종본을 다시 렌더하고 재생했다. [착안 러프 재생](harbor-landfall-draft-playback.jpg) · [컷의 연속성](harbor-continuity.jpg) · [최종 재생](harbor-final-playback.jpg)

제작자 판단으로는 마지막 귀환의 변화가 배의 밝기와 궤적으로 읽힌다. 원화의 인쇄 질감과 방위계의 입체 재질을 구분한 상태로 선의 위치를 이어갈 수 있었다. 후반에는 배와 오른쪽 등화 사이가 멀다. 관객이 두 사건을 어떻게 연결하는지는 미확인이다.

## 인쇄기

9초 동안 12프레임마다 글자를 교체하고 타격음을 넣는다. 한 줄, 어긋난 인쇄, 활자판의 반복을 거친 뒤 180프레임에서 한 단어로 잠근다. 별도의 공유 채널과 3D 없이 같은 도구로 구성했다. 제작자 판단으로는 마지막 정렬이 앞의 복잡한 반복을 한 번에 정리한다. 이 사례는 즉시 동기와 과밀화도 같은 엔진으로 전체 전개를 구성할 수 있는지 시험했다. [최종 재생](press-final-playback.jpg)

## 야간 분류함

별도 창작 의뢰와 음원으로 6초 작품을 제작했다. 스킬에서 안내한 초기화, 개정본 고정, 전체 렌더, 재생 검토와 동기 검사를 실행했다. 초안과 최종본의 차이, 입력과 실행 기록은 별도 문서에 있다. [제작 및 재생 검토](FORWARD.md)

## 기술 검증

- 환경은 Node v26.12.1, Chrome 156.0.8078.80, FFmpeg 및 FFprobe 9.0.2다. Canvas 2D와 WebGL 2를 실제 호출했다. [환경](doctor.json)
- `npm test`는 실제 Chromium에서 재생된 프레임을 임의 탐색의 상태와 PNG로 대조한다. 유지, 순간 교체, 빈 구간, 표식 변경, 구간 반복을 검사한다. 독립 모듈의 정지 렌더도 직접 평가와 바이트로 비교한다. 입력 각도 변경에 따른 3D 투영과 컷 뒤의 항로 변화, 동일 입력 재탐색, 베이크 JSON, 누락 자산, 실행 파일 오류와 취소 후 새 작업 재시도도 검사한다. 초기에 재생 콜백의 밀도를 실제보다 높게 가정한 실패가 있었다. 화면에 표시된 프레임의 일치와 오프라인 전체 출력 수를 구분했다. [최종 테스트](tests-final.log) · [실패 1](integration-attempt-1.log) · [실패 2](integration-attempt-2.log)
- 960×540 본편과 480×270 미리보기는 같은 개정본이다. 17·18·87·88·219·220·221·296·401·402·403프레임을 비교했다. 본편을 축소한 이미지와 미리보기의 RGB 평균 절대 오차는 0.48–2.87/255였다. 주요 단서인 방위계 포인터, 컷, 항로, 등화가 두 출력에 남았다. 비교 UI는 두 영상의 220프레임에 정지했고 각 독립 재생 버튼이 다른 영상을 정지시켰다. [프레임 비교](preview-visual-parity.json) · [UI](review-ui.json)
- 최종 H.264/AAC의 실제 비디오 PTS와 오디오를 디코드했다. 18프레임에서 +1.083ms, 402프레임에서 +0.729ms였다. 평균 고정 차이는 +0.906ms, 두 지점의 드리프트는 −0.354ms다. 허용치는 1프레임(41.667ms)이다. 432프레임이 모두 존재하며 두 스트림의 길이 차이는 0ms였다. 축소 MP4에서도 같은 수치가 나왔다. [최종 동기](harbor-final-sync.json) · [미리보기 동기](harbor-final-preview-sync.json)
- 구간 출력은 212–259프레임 48장과 오디오 2초를 결합했다. 최종 MP4 두 편을 오류 없이 전체 디코드했다. [구간 스트림](harbor-cut-ffprobe.json) · [출력 SHA-256](output-sha256.txt)

## 근거 범위

브라우저에서 각 후보의 인코딩된 MP4를 독립적으로 끝까지 재생했다. 자체 평가는 실제 재생에서 캡처한 이미지의 순서와 시각, 오디오 에너지 및 결합 파일의 타격 시점에 근거한다. 인터페이스에서 실제 소리를 직접 들은 청취 평가와 스피커·실기기 검증은 미확인이다. 헤드리스 브라우저 표시 콜백은 일부 프레임을 건너뛰었다. 완전한 프레임 수는 파일의 전체 디코드와 PTS 검사로 별도 확인했다.

관객 관찰과 사용자 수락은 미확인이다. 스킬 YAML은 검증기를 통과했고 실행 도구를 로컬에서 호출했다. 전역 설치, 자동 발견, 공개·배포는 이 작업에서 수행하지 않았다. 정수 FPS와 로컬 Chromium을 사용했다. 다른 브라우저·폰트·GPU 조합의 픽셀 동일성은 검증하지 않았다.
