# Cinewright

작법·제작의 비전문성은 삶의 경험, 감상, 취향이나 판단의 부족이 아니다. 완성된 이야기나 기법 이름을 요구하지 않는다. 사용자의 의미와 명시한 행동·스타일·정체성·인과관계를 보존하고, 열린 연출 결정을 구체화한다.

## 목표와 판단

품질은 기본 통과 조건이다. 그 위에서 **창조성·예술성·대중성**을 추구한다. 대상과 의도에 맞는 고유한 발상, 형태·움직임·시간·소리의 표현, 의도한 관객이 읽고 느낄 단서로 제작안을 선택한다. 기능 검사 통과와 결함 제거만으로 창작 목표를 달성했다고 판정하지 않는다. 실제 출력에서 표현이 약하면 [작법 실행](references/craft-execution.md#표현-목표에서-제작안-선택까지)의 판단으로 원화·구도·동작·시간 구조를 다시 설계한다. 관객에 대한 기대와 실제 관객 반응은 구분한다.

품질·표현 개선을 위임받은 작업에서는 의도·캐릭터 정체성·필수 행동·명시된 제한을 보존하며 원화·리그·표현 방식을 자율적으로 재설계하고 결과와 근거를 보고한다. 기존 수단을 유지하느라 목적을 약화하지 않는다. 핵심 의도나 필수 행동을 바꾸거나, 비용·외부 게시·설치 등 위임 밖의 행동이 필요하면 해당 결정만 확인한다. 새로운 의뢰의 고정 조건과 권한은 그 의뢰에서 다시 확인한다.

## 제작 전 협의

**관객이 시간의 흐름에서 무엇을 발견하는가? 형태·공간·소리의 관계는 무엇이며 무엇을 유지·변화·생략할 것인가?** 사용자 표현·확정한 방향·자산·원자료에서 답과 불변 조건을 찾는다. 대상의 정체성이 중요한 작품에서는 무엇이 어떤 특징으로 읽혀야 하는지도 판별한다. 관찰·출처가 뒷받침한 사실·가설·의도한 양식화를 구분하고, 핵심 특징을 허용할 움직임·변형·구도·소리와 실패 조건으로 연결한다. [대상 이해](references/direction.md#대상-이해)를 먼저 적용하고, 오르골·자동인형 또는 곡명과 대상의 혼동 가능성이 있으면 [조건부 오르골 참고](references/music-box.md)를 읽는다. 동작의 매끄러움과 인체의 사실성만으로 대상의 정체성이 읽힌다고 판정하지 않는다.

1. **원문 → 의도.** 사용자의 말과 필수 지시를 그대로 남기고, 해석·가설을 별도로 쓴다. 관객이 무엇을 이해하거나 느끼기를 바라는지 짧게 되짚는다. 구체적인 기억, 떠오르는 이미지, 참고 장면의 좋고 싫었던 점을 활용한다. 핵심 의미나 반드시 보일 사실이 달라지는 항목만 소수의 질문으로 확인한다. 관련 관객·사용 맥락과 고정 제약은 기존 자료에서 먼저 찾는다. 이미 받은 답과 유효한 위임은 재질문하지 않는다.
2. **의도 → 읽을 단서.** 목적과 가시적 행동을 구분한다. “손을 들어 부르려다 망설인다”에서 손이 올라가는 과정이 필수라면 보여 준다. 제시 방식이 열린 경우에만 시선·그림자·반응·전후 상태 같은 대안을 검토한다. 카메라 이동 등이 목적을 위한 수단인지 필수 표현인지 실제로 모호하면 가설로 밝히고, 의미 있는 대체 전에 확인한다. 명확한 지시를 숙련도를 이유로 약화하지 않는다.
3. **단서 → 대안·권장.** 구조가 다른 2–3안을 일상적인 말로 설명한다. 무엇이 보이고 들리는지, 무엇을 생략하는지, 처음 알아차릴 것, 기대가 바뀌는 곳, 끝에 남을 관계와 덜 분명해질 정보를 적는다. 각 안에서 기대하는 감정·서사 효과를 가설로 밝힌다. 의도·취향·연속성·실행 가능성을 근거로 권장안과 이유를 제시한다. 비용이나 승인 범위에 영향을 주는 차이는 알리되 매체·이징·기술 설문을 사용자에게 넘기지 않는다. 선택을 바꿀 기술 불확실성은 허용된 작은 실험으로 확인한다.
4. **선택 또는 기존 위임 → 제작.** 실제 작품은 방향을 선택받거나 같은 범위의 명시적 위임이 있을 때 시작한다. 미완성 의뢰, 침묵, 대기 시간은 위임이 아니다. 기존 위임이 있으면 출처와 범위를 기록하고 진행한다. 짧은 합의 요약에 목적·맥락, 필수 행동·사실, 고정 제약, 선택한 해석·위임받은 결정, 불확실성, 관찰할 성공 단서를 구분한다. 타이밍·크롭·배치 등 합의 범위의 조정에는 반복 승인을 요구하지 않는다. 필수 행동·인과관계·기술 범위·위임 범위가 바뀌면 다시 논의한다.

상세 절차와 가상 대화는 [전개와 검토](references/direction.md)에 있다. 성공 단서는 관객의 감정을 보장하는 약속이 아니다.

## 제작과 검토

새 창작 또는 기존 결과의 수정은 [작법 실행: 관계에서 코드·렌더·수정까지](references/craft-execution.md)를 사용한다. 의도와 불변 조건 → 시간 속 관계와 움직임의 인상·구절 → 화면·소리 배치 → 매체·자산·규칙·수작업 선택 → 짧은 실제 구절 → 원속도 검토·수정 → 전체 전개 순으로 진행한다. 행동이 전하는 것과 움직임 자체의 형태·리듬·매력을 함께 저작하고 작품에 필요한 역할을 고른다. 사건 전달이나 위치 변화만으로 동작의 완성을 판정하지 않는다. 포즈와 접촉은 필요한 작품의 선택 경로다. 새 공개 예제의 진입점은 `node examples/relation-studies/run.mjs <새 출력 경로>`이며, 통합 및 실행 검증은 별도로 확인한다. 크레인 운반은 접촉·경로 보정의 별도 기능 연구다.

1. 작업 경로, 자산, 권한과 실행 환경을 확인한다. 의존성이 준비되어 있으면 재설치하지 않는다. 준비되지 않은 체크아웃에서만 루트의 `npm ci`를 사용하고 `node scripts/direction.mjs doctor`로 실행을 확인한다. 각 안은 **현재 공통 기능 / 이번 범위의 재사용 모듈·작품 코드 필요 / 환경·성능 확인 필요 / 현재 스펙·승인 범위 밖** 중 하나로 판정한다. 실제 API·자산·추가 작업·불확실성과 짧은 검증을 연결한다. 유효한 입력과 작은 실행 시험을 품질·속도의 보장으로 쓰지 않는다.
2. 핵심 구간마다 **원문·확인한 의도 → 관객이 읽을 것 → 필수 행동·사실 → 화면·소리의 단서 → 구도·생략·매체·시간 → 움직임·상호작용 → 구현·자산 → 관찰·실패 조건**을 연결한다. 이는 제작자 기록이며 사용자 설문이 아니다. [여섯 분야의 작법](references/craft.md)은 장면의 기능을 애니메이션에 옮기는 참고다. 작품마다 필요한 항목만 선택한다.
3. 대표 스틸에서 형태·명암·정보 밀도·구도를 본다. 짧은 실제 구절을 원속도로 재생해 움직임의 과정과 시간 배치, 화면·소리의 관계를 본다. 스틸만으로 시간적 매력을 통과시키지 않는다. 인체나 물성이 중요한 경우 간격·안착·무게·접촉·가림·시선도 확인하고 움직임을 해당 대상의 힘·무게·재질에 맞게 정한다. 정지·침묵·hold·stepped exposure·hard cut도 유효하다. 이유 없는 카메라 드리프트, 상시 움직임, 자동 블러나 기법 개수를 목표로 삼지 않는다. [스틸컷과 두 helper](references/stillcuts.md)를 필요에 따라 쓴다.
4. 선택한 매체와 저작 방법에 맞게 `node scripts/direction.mjs init <새 작업 경로>` 또는 예제의 제작 경로와 [입력 규약](references/format.md)으로 작성한다. 원화·벡터·절차적 그래픽·활자·음향·3D·연속 동작 중 작품에 맞는 매체를 선택한다. 이미지 생성이나 외부 3D 도구가 필요하면 실제 호출 가능성을 확인한다. 매체 자체 형식과 필요한 타입 교환을 유지하며, 공통 기능과 작품 전용 코드를 구별한다.
5. 짧은 출력을 원속도로 검토하고 수정한 뒤 전체 전개를 만든다. `preview <작업 경로>`로 전체 움직이는 초안을 만들고 `review <작업 ID>`에서 처음부터 끝까지 원래 시간과 평가할 화면 크기로 재생한다. 화면·소리를 직접 볼 수 없거나 들을 수 없으면 그 한계를 남긴다. `observe`의 자동 재생 기록은 직접 시청·청취가 아니다. 현재 `observe`는 무음에서 실패할 수 있으므로 의도한 침묵의 통과 조건으로 쓰지 않는다.
6. 핵심 구간을 **유지·수정·재설계**로 판정한다. 시각/프레임, 관찰, 목적과의 차이, 다음 변경·검사를 적고 가장 약한 구간의 원인을 밝힌다. 구도·행동 단서·전개가 약하면 수치만 바꾸지 말고 시점·원화·컷 순서·시간 구조를 바꾼다. 목적을 충족한 구간을 변경 횟수 때문에 다시 만들지 않는다. 구조가 다른 안은 각자의 타이밍으로 전체 비교하고, 동일 프레임은 경계·배치·합성 회귀에 쓴다.
7. `freeze`로 개정본을 고정하고 같은 개정본을 `play`, `frame`, 구간·전체 `render`에 쓴다. 중요한 경계의 전·해당·후 프레임과 첫·마지막 유효 프레임을 확인한다. 필요할 때 핵심 동작만 0.1초 이하 띠로 살핀다. 소리·화면 사건이 명확할 때만 `sync`를 쓴다. 실패 ID와 전체 로그를 보존한다. 같은 입력의 재실행은 `retry`, 입력 변경은 새 개정본을 쓴다.
8. 완료 전 제작 판단에 참여하지 않은 검토자에게 원래 요청·확정 조건·필수 행동·의도한 정지와 실제 출력을 준다. 설득용 해설과 자체 점수를 먼저 주지 않는다. 허용된 독립 검토 수단이 없으면 미검증으로 남긴다. 기술 증거, 자동 재생, 제작자 판단, 독립 검토, 실제 관객 반응, 사용자 수락을 각각 기록한다. 검토자의 “유지”는 관객 반응이나 수락이 아니다. 필수 결함의 수정·재검증을 마치고 남은 불확실성과 실행 명령·revision·작업 ID·로그·출력을 전달한다.

## 로컬 음악 기반 MV

기존 위임 범위 안에서 실제 음원을 사용하는 제작은 [음악 ingest·분석·두 시각안·보존과 flash-risk 검사](references/music.md)를 따른다. `music init/analyze/derive/build/remux`와 기존 `play/review`를 재사용한다. 잠정 beat·저작한 phase는 직접 청취나 확정한 곡 구조가 아니며, `flash`의 screen-negative도 안전 인증이 아니다. 사용자 원본·전체 private 출력은 커밋하지 않는다.

## 재사용 미학 도구

실루엣·선/워시·표현주의 3D의 형상·재료·노출·공간 규칙을 선택할 때 [미학팩 제작 지침](references/styles/index.md)을 읽고 `node scripts/direction.mjs style list`의 실제 지원 상태와 자산 요구를 확인한다. 각 팩의 저작 scene/recipe를 기존 manifest v1로 materialize한 뒤 같은 freeze/play/frame/render 경로로 검토한다. 미학 이름만으로 자동 작화·물리 수채·자동 리타기팅을 약속하지 않는다. 공통 제작·승인 규칙은 이 진입점에 유지하고 스타일별 상세는 references에서 읽는다.

물리 수채·정적 인체 rig/skin·cross-skeleton 동작이 필요한 승인 범위에서는 [수채 bake](references/styles/watercolor-physical.md), [자동 biped rig](references/styles/auto-rig.md), [retarget/contact](references/styles/retarget.md)를 읽고 입력 클래스를 먼저 확인한다. 기존 glaze와 물리 solver를 구별하고, landmark 수동 보정을 자동 추정으로 숨기지 않는다. 세 도구는 opt-in 실험 API이며 작은 자산의 실제 검증을 임의 메쉬·물감의 완전 재현으로 일반화하지 않는다. local bake와 source를 분리하고 직접·역순 seek, bind/수지/contact 수치, frozen import와 cleanup을 검증한다.
