# Cinewright

1. 창작 의뢰는 사용자가 원하는 스타일과 스토리를 중심으로 받는다. 실제로 지정된 길이·화면 비율·원본·권한은 고정 조건으로 함께 보존한다. 매체, 카메라, 장면 수, 움직임과 음향 배치는 제작 과정에서 도출한다. 작업 경로를 정하고 이 스킬의 루트에서 `npm ci`, `node scripts/direction.mjs doctor`를 실행한다. 설치·도구 발견·실제 실행을 구분한다.
2. 전체를 조직하는 방식이 다른 후보를 비교한다. 시작에서 무엇을 알아차리고, 어느 변화에서 기대가 달라지며, 끝에서 무엇을 다시 보거나 듣는지 적는다. 컷, 정지, 과잉, 동시성, 생략도 선택할 수 있다. 신과 표식은 탐색에 쓴다.
3. 선택한 방향의 대표 화면에서 형태의 묘사 수준, 선과 가장자리, 명암, 재질, 공간 관계를 정한다. 서로 다른 매체가 만나는 부분은 움직임까지 포함해 시험한다. 중요한 대상을 놓치거나 접촉·가림이 어긋나면 해당 표현을 바꾼 뒤 전체 초안에 반영한다. `node scripts/direction.mjs init <새 작업 경로>`로 시작한다. [입력 및 모듈 규약](references/format.md)에 따라 `work.json`, 자산, 모듈을 작성한다. 원화 생성에는 사용 가능한 이미지 도구를 직접 호출한다. 3D는 필요한 경우 Three.js 모듈 또는 외부 도구로 만든 소스·베이크를 사용한다. 각 매체의 자체 형식을 유지하고 실제로 필요한 값만 연결한다.
4. `preview <작업 경로>`로 처음부터 끝까지 움직이는 초안을 만든다. `review <작업 ID>`에서 소리와 함께 재생한다. 로컬 Chromium 재생을 기록하려면 `observe <작업 ID>`를 실행한다. 재생 로그와 프레임은 자동 증거다. 직접 듣고 본 판단이나 관객 반응으로 기록하지 않는다.
5. 전체 재생에서 시선이 끊기거나 관계가 드러나지 않는 시점을 찾는다. 먼저 무엇을 보지 못했는지 적고 구도·매체·순서·지속 시간 중 원인에 맞는 항목을 수정한다. 발견이 구조에 영향을 주면 현재 안과 시작·발전·결말을 바꾼 안을 각각 원래 타이밍으로 끝까지 재생한다. `play`와 `frame`으로 결정적인 단서와 직전·직후 프레임을 확인한다. 같은 시각의 비교는 회귀 확인에 쓴다.
6. `freeze`로 개정본을 고정한다. 같은 개정본을 `play`, `frame`, `render`에 넘긴다. 영상에 명확한 소리와 화면 사건이 있다면 초반과 후반에 검사용 표식을 작성하고 `sync`로 실제 MP4를 확인한다. 실패한 작업의 ID와 로그를 남긴다. 같은 입력으로 다시 실행할 수 있으면 `retry`를 사용하고, 입력을 고쳤다면 새 개정본을 만든다.
7. 영상과 개정본, 실행 명령, 기술 검증, 재생에 근거한 자체 판단을 전달한다. 자체 판단은 시점과 관찰한 화면에 연결하고 남은 약점을 적는다. 관객의 관찰과 사용자 수락은 각각 근거가 생겼을 때 기록한다. 전역 설치와 공개 배포는 별도 권한을 확인한다.
