# 신호의 항구 · 밤의 통로

24초, 1600×900, 24fps 영상으로 다시 제작했다. [영상](../../outputs/harbor-v2/harbor-v2.mp4)과 [기존안 비교 화면](../../outputs/harbor-v2/index.html)에서 각각 원래 속도로 재생할 수 있다.

검증 의뢰는 [스타일과 스토리](STYLE-STORY.md) 두 항목이다. 모형의 형태, 길이, 카메라, 빛과 음향, 검사 방법은 제작자가 도출했다. 같은 컨텍스트에서 기존 구현과 실패를 알고 진행한 자체 검증이다. 독립된 블라인드 검증은 미확인이다.

## 선택과 변경

판화가 접히는 해안, 입체 항구, 지워지는 해도를 비교했다. 배와 수면의 접촉, 빛과 통로의 관계를 같은 공간에서 다룰 수 있는 입체 항구를 선택했다. 후보별 전개와 미해결 항목은 [제작 계획](PLAN.md)에 기록했다.

기존의 해안 원화, 도판과 독립 방위계 대신 새 선체·등대·암초·부두를 만들었다. 무광 도장과 단순화한 암석 면을 사용했다. 바다에는 시간으로 계산한 파형과 잔물결을 넣었다. 배의 높이는 그 위치의 파고에 맞춘다. 항적은 배가 지나간 위치에서 생성한다. 선체와 난간, 건물과 등대의 가장자리는 동일한 조명 아래에서 렌더한다.

전체 초안은 배, 등대, 항구를 세 컷으로 보여 줬다. 재생 기록에서 11초 컷 뒤 배가 작아지고 마지막 도착도 먼 구도에 머무는 것을 확인했다. 수정본은 4.2초부터 배를 따라가던 카메라가 멀어져 통로를 보여 주고, 17초부터 부두로 접근한다. 마지막에는 부두의 불빛과 창문이 배에 응답한다. [세 컷 초안 재생](draft-playback.jpg) · [구조 수정본 재생](revised-playback.jpg) · [최종 재생](final-playback.jpg)

대표 화면에서는 지붕의 방향, 등대 줄무늬 가림, 규칙적인 바위 층과 각진 항적을 발견했다. 지붕은 경사면으로 다시 만들고 줄무늬를 탑 표면 밖에 배치했다. 바위는 불규칙한 덩어리로 바꿨다. 항적은 시작 시각 이전의 점을 숨기고 폭과 밝기를 줄였다. 최종 비교 화면에서 등대 창문 가장자리의 삼각형 결함을 발견했다. 그림자를 끈 진단 렌더에서도 결함이 남아 형상 겹침으로 원인을 좁혔다. 창문 위치를 높이별 탑 반지름으로 계산한 뒤 창문 전체가 보이는 것을 확인했다. [첫 대표 화면](style-wide.json) · [첫 배 화면](style-72.json) · [수정 후 화면](style-revised-72.json) · [그림자 가설 검사](tower-shadow-fix.json) · [창문 형상 수정](tower-window-fix.json)

## 재생에 근거한 자체 판단

- 0–4초에는 배가 화면에서 충분한 크기를 차지한다. 난간, 선실과 선체가 구별된다. 1초의 등화 변화는 최종 파일의 24프레임에서 확인했다.
- 6–12초에는 동일한 배가 화면 안에 남은 상태로 두 암초와 해안이 드러난다. 기존의 도판 전환과 비교해 배가 지나갈 공간의 위치를 이어서 볼 수 있다.
- 19–24초에는 카메라가 부두로 접근한다. 21초의 부두 불빛과 창문 변화 뒤에 배가 부두 옆에서 멈춘다. 도착 위치와 응답의 발신지가 같은 화면에 남는다.

전체 재생은 로컬 Chromium의 실제 시간 재생을 기록했다. 모델의 시각 평가는 그 재생에서 캡처한 화면의 순서와 실제 시각, 추가로 추출한 프레임에 근거한다. 최종 관찰에서는 표시 콜백이 526개였고 처음 포착한 시각은 0초, 마지막은 23.958초였다. 전체 576프레임의 존재는 파일 디코드와 PTS 검사로 별도 확인했다. 실시간 합성기의 12개 재생 화면도 직접 탐색 화면과 대조했다.

암초의 면 분할과 선체의 단순화는 화면에 뚜렷하게 남는다. 항적은 가는 선으로 표현되어 물의 질량감이 약하다. 부두에 닿는 마지막 구간의 계류 동작은 생략했다. 직접 청취, 실제 관객 반응과 사용자 수락은 미확인이다.

## 기술 검증과 보존

- 최종 576프레임과 오디오 24초를 전체 디코드했다. 24·504프레임에서 화면 표식이 나타났다. 대응 오디오 피크는 각각 +15.021ms, +8.833ms였다. 평균 차이는 +11.927ms, 두 지점의 피크 차이 변화는 −6.188ms다. 한 프레임인 41.667ms 허용치 안이다. 음의 공격 시간과 배경음도 피크 위치에 영향을 줄 수 있다. [최종 동기](final-sync.json) · [스트림](final-ffprobe.json)
- 13개 지정 프레임을 추출하고 그중 9개를 순서를 바꿔 재평가했다. 같은 프레임의 PNG가 정확히 일치했다. 실시간 재생에서 12개 화면을 채집해 직접 탐색한 화면과 픽셀 단위로 대조했다. 주요 암초 두 곳과 안쪽 부표의 경로 여유도 확인했다. [검사 결과](final-work-check.json) · [재실행 코드](verify-work.mjs)
- 동일 개정본의 800×450 미리보기와 1600×900 최종본을 11개 프레임에서 비교했다. 최종본을 축소한 이미지와 미리보기의 평균 RGB 절대 차이는 0.80–1.29/255다. 배, 통로, 등화와 부두 응답이 두 출력에 남았다. [비교 이미지](preview-final-comparison.jpg) · [수치](parity.json)
- 48kHz 스테레오 1,152,000샘플 원본과 인코딩 전 믹스는 signed PCM으로 디코드했을 때 바이트 단위로 일치했다. 음악은 고정 시드와 직접 작성한 타격 시각으로 새로 합성했다. [합성 코드](../../examples/harbor-v2/score.py) · [기록](audio-authoring.json)
- 기존 항구 입력, 최종 MP4와 이전 검토 문서의 해시가 유지됐다. [보존 및 출력 해시](delivery-check.json)
- 시간축과 렌더 엔진의 소스는 이번 작업에서 변경하지 않았다. 기존 8개 테스트의 통과 근거에 더해 새 작품의 재생·탐색·경로·최종 출력 검사를 실행했다.
- 비교 화면에서 24초·18초 영상을 각각 재생하고, 21초로 직접 이동한 뒤 다른 영상 재생 시 기존 영상을 정지하는 동작을 확인했다. 390px 화면의 가로 넘침과 페이지 오류도 없었다. 최초 단순 HTTP 서버의 바이트 범위 요청 미지원 때문에 탐색이 실패해 기존 미디어 서버를 재사용했다. [UI 검사](review-check.json) · [탐색 실패 로그](review-check-http-range-failure.log)
- 스킬 YAML 검증기가 통과했다. 검증 의뢰를 스타일과 스토리로 작성하고, 제작자가 선택한 구체적 방법을 결과 기록에 두도록 바꿨다. 대표 화면의 묘사·접촉 관계와 전체 재생의 시선 단절을 찾아 수정하는 절차도 보완했다. 최종 재생을 다시 검토할 때 이 절차를 적용했다. [스킬 수정과 적용](SKILL-CHANGES.md) · [YAML 검사](skill-validator.log)

첫 프레임 출력은 음원이 아직 없어서 실패했다. NumPy가 없는 Python 환경에서는 음원 합성 시도가 실패해 표준 라이브러리 구현으로 바꿨다. 검증 스크립트의 작업 디렉터리 생성 누락도 수정했다. 카메라를 변경한 뒤 투영 좌표를 계산할 때는 카메라 행렬을 먼저 갱신하도록 고쳤다. PyYAML이 있는 시스템 Python으로 스킬 검증기를 실행했다. [음원 누락](style-wide-missing-audio.json) · [검사 디렉터리 누락](work-check-missing-directory.log) · [스킬 검증 환경 실패](skill-validator-python-env-failure.log)
